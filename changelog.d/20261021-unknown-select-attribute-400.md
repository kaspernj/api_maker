A select payload asking for an attribute the resource does not expose now answers 400 with the resource and attribute name (`type: unknown_select_attribute`) instead of crashing with a 500 `RuntimeError` and filing a server-side bug report. `ApiMaker::SelectParser` raises the dedicated `ApiMaker::UnknownSelectAttributeError` (the unknown attribute is still rejected loudly - never skipped), the command executor validates every pool select before any command runs, the websocket channel reports a failed request without dropping the connection, and each rejection logs with a process-wide counter plus path/method/user-agent so the calling client can be identified.
