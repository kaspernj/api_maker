Command request retries no longer swallow the real failure. When `ApiMakerCommandsPool#sendRequest` exhausts its retries (e.g. a persistently invalid authenticity token), it now throws a `CustomError` whose message names the last response type and whose `args.response` carries the last real response, instead of a generic "Couldnt successfully execute request". Bug reports and consuming error handlers therefore see the actual cause (e.g. `invalid_authenticity_token`) rather than an opaque message.

`ApiMakerSessionStatusUpdater#updateSessionStatus` now skips applying a session-status result when the CSRF token changed while the request was in flight (a sign-in rotating the token) and logs that skip. This guard previously only existed as a consumer monkey-patch that discarded the result silently; the logic now lives in the library and reports when it fires, so consuming apps can drop the override.
