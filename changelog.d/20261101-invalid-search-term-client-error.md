A command payload whose Ransack search term cannot be resolved (for example an index command with `q[:accessible_from_lte]`, where Ransack only registers `lteq`) no longer escapes as a reported production error. With `ignore_unknown_conditions = false` Ransack raises instead of skipping the key, and that raise used to be classified `runtime_error` — "Internal server error" for the client plus a bug report. The command now answers with a dedicated per-command error (`type: invalid_search_term`) naming the offending key, the rest of the batch runs normally, and the rejection is logged with request attribution plus a process-wide counter instead of being reported as an application error.
